## Run (development)

```bash
cd backend
python -m venv .venv && .venv\Scripts\activate     # optional
pip install -r requirements.txt
export SECUREHEALTH_DATABASE_URL="postgresql+psycopg://user:pass@localhost/securehealth"  # production target
python -m alembic upgrade head                      # apply migrations
uvicorn app.main:app --reload --port 8000           # Swagger: http://localhost:8000/api/docs
pytest tests -q                                     # 44 passing (incl. node-vs-python FL/ledger parity + AI/regulator/sweep)
cd ../e2e && npx playwright test                    # 4 browser E2E (auto-starts both servers)
```

Notes (documented per spec):
- **SQLite is never a target care-platform database.** It is the local dev/test
  convenience here only; `create_app()` refuses SQLite in `SECUREHEALTH_ENV=production`,
  along with default JWT secrets and disabled security scanning.
- CORS is the outermost middleware and OPTIONS preflights are never rate-counted; a 429 therefore surfaces to the browser as a clean RATE_LIMITED error (found and fixed via browser E2E).
- The in-process sliding-window rate limiter is the dev/test implementation;
  production uses Redis (tracked gap, Phase 12).
- JWT transport today is `Authorization: Bearer`; the production browser target is
  secure httpOnly cookies + CSRF (frontend phase).
- Seed SYSTEM_ADMIN (`system-admin@example.com` / `SystemAdmin#2026`) is created only
  in non-production for admin-flow testing; production provisioning is deployment concern.
